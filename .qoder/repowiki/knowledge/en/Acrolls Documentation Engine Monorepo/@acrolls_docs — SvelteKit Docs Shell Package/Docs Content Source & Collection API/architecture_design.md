Four cooperating modules form a layered pipeline: `content.ts` is the core engine — `createDocsContentSource()` builds a typed `DocsContentSource` (nav, documents, diagnostics, get/load/entries) from raw `DocsContentInput[]`, applying naming conventions (`numbered`, `dated`, `passthroughNaming`), route overrides via `config.entries`, folder/document config, authored-mode admission rules, and diagnostic collection. `collection.ts` sits on top as the host-facing API: `content(options)` wraps a `ContentLoader<TDocument>` through a validate → filter → admit pipeline, exposing `source()`, `sourceSync()`, `get()`, `list()`, `ids()`; it declares the `StandardSchemaV1` interface so hosts plug in Valibot/Zod/Arktype without adding a dependency. `fields.ts` provides hand-written `StandardSchemaV1` validators for Acrolls' own frontmatter fields (`acrollsFields.page`, `post`, `change`) that normalize and pass through unknown keys. `merge.ts` composes multiple `ContentLoader`s into one with optional `prefix` key namespaces and a matching `mergeRaw` for raw markdown maps, ensuring eager semantics propagate only when all sources are eager. Dependency direction is strictly inward: `collection.ts` imports from `content.ts` and re-exports `mergeLoaders`/`mergeRaw`; `fields.ts` depends only on `collection.ts` types; `merge.ts` depends only on `content.ts` error type and `collection.ts` loader types — no reverse imports.
