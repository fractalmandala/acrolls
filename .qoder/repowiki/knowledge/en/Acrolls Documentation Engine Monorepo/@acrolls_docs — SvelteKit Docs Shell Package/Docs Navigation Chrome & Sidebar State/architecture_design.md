Pure-function utilities in `nav.ts`, `toc.ts`, and `storage.ts` operate on the shared `DocsNav` / `DocsNavSection` / `DocsNavNode` types declared in `types.ts`, while path helpers (`normalizePath`, `slugify`, `stableId`) live in `nav-path.ts`. `nav.ts` is the central hub: it derives stable ids via `withNavIds`, flattens trees with `flattenDocsNav`, resolves the active item/section/trail for a pathname, builds breadcrumb crumbs and pager links, and computes which sections/nodes should be open. `storage.ts` persists per-nav open-state under a `acrolls-docs:open:` prefix in `localStorage`, guarded by the `browser` flag from `browser.ts` so SSR runs safely. `toc.ts` scans a DOM subtree for headings into `DocsTocItem[]`, optionally auto-assigning unique ids. The Svelte components (`DocsSidebar.svelte`, `DocsNavTree.svelte`, `DocsBreadcrumbs.svelte`, `DocsPager.svelte`, `DocsToc.svelte`, `DocsPageHeader.svelte`, `DocsAccordion.svelte`, `DocsShell.svelte`) consume these utilities and are re-exported through `index.ts`, which also aggregates content-collection, SEO, OG, and AI exports — this module's scope is specifically the navigation chrome surface.
