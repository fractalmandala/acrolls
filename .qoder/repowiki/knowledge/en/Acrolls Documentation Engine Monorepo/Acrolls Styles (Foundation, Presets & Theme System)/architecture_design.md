The package exposes five importable surfaces — `foundation`, `default`, `docs`, `colors`, `theme` — each available as both precompiled `.css` and source `.sass`. Source lives under `src/` and is compiled to the package root by `scripts/build.mjs`, which runs `sass` with `--pkg-importer=node` so `@forward 'pkg:fractalthemer/...'` resolves at build time. Internally the styles are layered in strict emission order: `_scheme.sass` defines the self-contained light/dark baseline on `:root` using fractalthemer-shaped tokens (`--bg`, `--text-primary`, `--theme-color`, …); `_bridge.sass` maps those tokens onto shadcn-style names (`--background`, `--card`, `--accent`, …) via runtime `var()` with Open Color static fallbacks; `foundation.sass` consumes the bridge tokens to style prose elements (`.acrolls` scope, code frames, tables, callouts, banners, zoom dialog, mermaid). The `theme` entry point forwards `fractalthemer` themes, auras, and theme-picker after the scheme+bridge so named `.theme-*` classes override the baseline by source order. A separate `_tokens.sass` exposes `$acrolls-tokens` and an `acrolls-tokens()` mixin for host projects that compile their own SASS. `package.json` declares `sideEffects` for the CSS entry points and lists `fractalthemer` as an optional peer dependency, keeping the lean `colors` preset free of runtime deps.
