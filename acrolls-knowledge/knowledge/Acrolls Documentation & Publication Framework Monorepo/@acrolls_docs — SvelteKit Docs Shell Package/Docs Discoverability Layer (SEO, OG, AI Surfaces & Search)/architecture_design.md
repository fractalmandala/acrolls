Four sibling files form the discoverability layer of `packages/docs`, each with a single responsibility and no runtime dependencies on SvelteKit or the host framework:
- `seo.ts` is the core: `buildDocsSeo` resolves per-page title/description/canonical/robots by merging frontmatter overrides (`metadata.seo`) over document fields over site defaults, emits Open Graph and Twitter meta maps, and builds JSON-LD (`WebSite` for index, `TechArticle` + `BreadcrumbList` for pages). It also exports `docsSitemap` and `docsRobots` to emit XML/text assets from a `DocsContentSource`.
- `og.ts` defines a pure Satori element-tree DSL (`acrollsOgCard`) producing a 1200×630 branded card; `docsOgSlug`, `docsOgImagePath`, and `docsOgEntries` derive filesystem-safe flat slugs (nested paths flattened via `/` → `--`) so a single `og/[slug]` route can prerender one PNG per document. Rendering itself is delegated to the host via `satori` + `@resvg/resvg-js`.
- `ai.ts` exposes static AI surfaces: `docsLlmsTxt` (compact index), `docsLlmsFullTxt` (concatenated raw Markdown keyed by `doc.key`), and `docsPageMarkdown` for per-page `.md` endpoints. Documents opt out via frontmatter `ai.exclude`; hidden docs are always skipped.
- `DocsSearch.svelte` is a Svelte 5 component that dynamically imports the Pagefind runtime at `bundlePath` (default `/pagefind/pagefind.js`) only on focus, debounces input at 160 ms, caps results via `maxResults`, and degrades gracefully when the index is missing (status `unavailable`).

Dependency direction is inward-only: all four files import shared types from `./content.js` and `./types.js`, and `seo.ts` additionally calls `buildDocsCrumbs` from `./nav.js`. Nothing in this module imports back into content/navigation generation, keeping it a leaf consumer of the content tree.
